## 不变量与边界

- D 提供身份、主数据、开放规则、时长配置及审计的模块公开服务。M1 只写自己的业务表，通过 D 公开服务读取/校验主数据并记录审计。
- 同一教室的所有分配和释放通过同一 PostgreSQL 事务级 advisory lock；随后重新读规则/占用并写入，事务内没有 HTTP。相邻区间 [start,end) 不冲突。同座位重叠再以 btree_gist 排斥约束兜底。
- 只接受含时区时间，按 Asia/Shanghai 检查整点及开放日。无开放规则拒绝，不用“默认全天开放”制造可用性。
- 公开写幂等键按“用户 + UUID”全局划定，指纹含操作/规范化参数；只保存已提交成功响应，重放返回该命令时的快照，不代表对象当前状态。改变操作/参数返回 409；失败事务不留下成功回执。
- 内部命令按 operationId 全局持久记录成功及明确业务失败；相同 ID 改内容拒绝。按来源保留递增 revision、来源 ID 和 RELEASED 墓碑。释放先于建立也写墓碑；新 ID 的旧版本、同版本和已释放来源的再次建立均拒绝。历史成功命令重放返回历史回执，来源 GET 才是当前状态，调用方须通过 revision/state 防止旧回执覆盖新本地状态。
- 服务调用凭据与用户会话分开。M2 专用凭据只可访问 M2 资源来源；另须校验实际 actorId 在 D 中有效，且具有作用于该教室的权限。workflow 必须在业务层确认真实申请人与当前审批人，核心不复制工作流所有权事实。凭据缺失时接口关闭；浏览器令牌不能访问内部命令。
- 不新增包、镜像或系统配置。新迁移追加、不清库；内部凭据仅在测试进程环境使用随机值。持久写入本地 .env 会另行征得环境所有者同意。

## 验收

真实数据库和 HTTP：非法时间、时长、开放时段、院系限制、停用资源、他人历史/取消；同座位并发仅一次成功，相邻时段可用；持有教室锁时写入必须等待；个人预约与整室占用并发不得同时成功；整室释放不误删维修来源；重试/换内容/旧版本/释放先到/重启后来源仍正确。故意破坏教室锁后同一测试必须失败。公共页面和 AI 交接任务随实际实现更新，未完成保持显式状态。
