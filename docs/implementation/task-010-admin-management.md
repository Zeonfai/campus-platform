# TASK-010：公共管理初版

2026-10-26。用户明确要求先推送上轮再继续剩余功能。TASK-009已提交5d1a3f7并推送feat/booking-lifecycle；本轮从该提交建立feat/admin-management，不代表主分支合并或人工验收。

## 目标与范围

补齐原D的12个占位及读取开放规则的新接口，关联D-002/004/005/007/008，保持M1唯一资源分配入口、双服务分库/HTTP边界。新增/admin真实管理页面，读写角色/院系/用户授权/房间座位/开放规则，查询core审计。不新增依赖或改系统/私密配置；保留已有迁移，只追加版本字段和审计理由。

## 简单初版决策

- 服务器生成实体UUID；院系名称、角色名称、教室编号、教室内座位编号保持数据库唯一约束。名称去首尾空白，教室/座位编号去空白并统一大写（避免仅大小写不同的重复资源）；不物理删除有历史的资源。
- 所有成功写入有用户作用域UUID幂等收据、绑定规范化内容，重放返回当时结果；随后GET取当前。修改提交expectedRevision，冲突409要求重新读取，避免覆盖他人修改。
- 院系登记/改名、角色管理、用户授权及审计查询仅对应动作ALL权限。不能借用无关权限扩大范围。不能授予操作者不具备的权限或更大范围。
- 用户管理针对已有账号做启停/角色/指定教室授权，不提供公开注册、批量导入或改密码。仅返回公开字段，理由必填；变更同事务撤销目标所有会话，重新登录后取得新权限。禁止自行更改本人授权；全局安全锁、锁后重读操作者与至少一名有效全域安全管理员保护防止并发撤空管理能力。演示账号不代表正式用户目录。
- 房间/座位写入要求该动作ALL、同院系DEPARTMENT或明确MANAGED_ROOMS；公共教室不扩大管理权限。新建房间须ALL或同院系权限，未知房间不能通过指定教室范围创建。
- 教室创建后固定院系归属与专属属性，修改这两项拒绝409；需要调整先新建教室并停用旧教室，不擅自修改已有M2/M3工单的范围事实。资源启停/改名和开放时间操作必须竞争M1同一room事务锁。停用阻止新预约，保留已有占用/历史，不能直接把M1记录删除或设为空闲。
- 开放时间按Asia/Shanghai、整点配置。外部星期1～7为周一至周日，数据库周日0。每次PUT以当前room revision替换整周，选中日各一个时段，支持结束24:00，不支持跨日单段；weekdays为空表示整周关闭。GET返回当前全周配置与room revision；PUT改为200返回新快照（原204仅未实现草案，无已用业务客户端）。
- 新房间没有开放规则就不可预约；不默认开放全天。缩短/关闭时间不追溯取消既有预约，新分配遵守新规则。
- 核心审计查询可按actorId/action/targetId精确筛选和分页，展示理由、时间、traceId，不含密码/令牌/签到码。workflow自己的审计仍留在workflow，不能把core列表冒充全系统跨库汇总。
- 公共输出revision为兼容旧内部投影可选；管理目录和管理写响应实际提供revision，页面不得猜测版本。

## 验收
