# TASK-009：预约签到与站内通知初版

日期：2026-10-23。用户授权继续开发；未明确流程采用简单可实现默认，体验后再修改。本方案是初版设计，不是全组共识或验收记录。

## 范围与关联

M1-004～010、INT-002；D-005、D-006 的站内通知部分。补齐签到、每日码、提醒/违约、再次预约、占用来源、统计、预约政策和对应页面。只追加数据库迁移，沿用真实 PostgreSQL、M1 教室锁、用户幂等键及动态权限。外部邮件/微信、违约申诉/封禁、D 主数据管理与云部署仍单列待办。

## 可体验默认决策

- 时间按 Asia/Shanghai。签到窗口为 [开始前15分钟, 开始后15分钟)，截止瞬间不再接受签到。所有时间判断取锁后数据库时间；后台默认每5秒扫描持久任务。
- 管理员查看当天本教室8位十六进制码；学生仅能输入码。每日/每教室独立随机生成，不允许跨教室或跨日复用；界面显示日期。错误码每预约每分钟最多5次，达到阈值临时锁定；无密码、签到码或请求体进入审计。
- 提前提醒设0表示关闭开始前提醒；开始后提醒仍按配置执行。
- 开始前15分钟发站内提醒，开始后10分钟仍未签到发第二次；开始后15分钟取消、释放并记录一次违约。重启只处理当前仍有意义的阶段，过期提醒不补发。签到与超时竞争同一教室锁；状态、违约、通知同事务。
- 上线前已存在的预约不追溯处罚，迁移标记免违约；仍会释放过期预约。新增预约才启用未签到违约。
- 违约暂不扣分或封禁；本人历史展示原因。资源停用或签到窗口内受已记录维修影响时，取消但免违约，通知联系管理员。维修来源新增首次releasedAt时间事实（重复释放不延长），用于判断，既有预约不因新增维修立即消失。
- 签到后到结束时间自动完成；初版不做提前离场、实际在场监测。取消仍限开始前未签到预约。
- 再预约沿用本人历史的座位，用户选择新时段，重新执行全部预约规则。不是周期预约，也不继承签到状态。
- 政策有递增版本；修改须提交当前revision避免覆盖。新预约冻结时间参数和政策版本，旧预约不被追溯改变。默认最多4小时；签到提前0～60分钟、超时1～60分钟，二次提醒必须早于超时。
- 管理读操作仅按该动作的 ALL、指定教室、相同院系授权，公共教室不扩大院系管理权限。本人通知不提供任意收件人参数。
- 统计指定含时区整点区间，最大31天，按教室分页；只统计个人座位预约。bookedHours为与区间交集的有效预约座位小时（BOOKED/CHECKED_IN/COMPLETED）；checkedInHours为已签到/完成预约交集小时，是预约时长代理，不宣称真实在座时长。同时列状态计数，不把M2/M3占用计入个人签到时长。
- 来源查询按时间筛选个人预约、整室占用及维修，保留来源ID/状态，管理员只看到管理范围内信息；不暴露学生姓名、签到码或服务凭据。
- 站内通知按事件+收件人唯一，已读写入幂等。站内可读不等于外部投递；没有外部账号/凭据与真实接收证据时，D-006外部渠道仍未完成。
