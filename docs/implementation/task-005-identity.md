# TASK-005：身份与主数据只读切片

日期：2026-10-15。状态：实现提案与验收范围，待人工评审；不是全组政策决议。

关联 D-001、D-002/003 的授权基础、D-004 的只读基础、D-007 的会话审计、ENG-007/008。先完成登录、退出、当前用户、按权限和范围读取院系/教室/座位，再进入 TASK-006 的跨服务申请样例。

## 范围与约束

- 仅修改 resource-core 的 D 模块、该服务的增量 Prisma 迁移、公共契约、web 的 D 页面及必要启动/验证文档；workflow 不连接 core 数据库。
- 使用现有 Node crypto 的异步 scrypt（N=131072、r=8、p=1、随机 16 字节盐）保存密码；不自制 JWT，不增加依赖。随机 32 字节 opaque bearer 会话，数据库仅保存 SHA-256 摘要，绝对期限 1 小时，无自动续期。会话不能在 URL/日志出现。
- 浏览器令牌仅留在 Pinia 内存，刷新后重新登录；退出立即在数据库撤销。用户禁用、角色/权限/管理范围变化在下一次请求生效。生产上线还需 HTTPS、密码生命周期/找回、凭据轮换和运维策略。
- 登录每个实际连接 IP 每 15 分钟最多 30 次、每个账号最多 10 次，计数落库、跨重启保留；不信任客户端 X-Forwarded-For。每进程最多同时进行两次密码计算，超额返回 429。部署可信代理时须单独评审来源 IP 配置。
- 授权取角色中该权限对应的范围并集，不能把另一个角色的 ALL 范围借给无关权限。SELF 不能读取资源目录；DEPARTMENT 读取本院系及非院系受限教室，MANAGED_ROOMS 只读取指定教室，ALL 可读取全部。目录不是可预约性查询，停用状态原样展示，预约规则仍由 M1 检查。
- 本轮不提供角色/用户/主数据写接口；动态角色和权限从数据库读取，配置管理 UI/API 留给 D 负责人，不把授权基础宣称为完整 D-002。
- 退出按 bearer 摘要幂等，带合法 Idempotency-Key，已撤销/未知格式合法令牌均返回 204，不披露令牌存在性。登录和退出成功事实与会话变更同事务审计；失败登录统一 401，不区分用户不存在、禁用或密码错误。

## 演示数据

基础 seed 仍只创建服务元数据。单独的本地 demo seed 仅允许 development/test + 127.0.0.1 数据库；在 `.local/demo-accounts.json` 生成随机密码（0600、Git 忽略），使用固定 demo ID 和 create-only upsert，重放不重置密码、权限或用户后续编辑。包含两个合成院系、三个教室、三类插座、普通目录读者及全域/院系/指定教室管理员，用于权限验收。这些角色只是隔离的技术样本，不决定正式申请资格、审批角色或正式账号名单（Q-001/Q-004 仍待定）。

## 验收

真实 PostgreSQL + 真实 HTTP 验证：正确/错误/不存在/禁用登录；非法输入；无令牌访问；会话数据库只存摘要；退出重放和失效；过期失效；动态撤权；不同权限的范围不串用；院系/指定教室隔离及越权座位查询；分页不越界；并发限流、账号/IP 限流和进程重启保留。测试账号在事务/专用前缀下建立并定向清理，不清库、不重置卷。

保留新增迁移历史，重跑迁移与 demo seed 检查幂等。新增表不改写已执行的基础迁移。检查结构、lint、类型、构建及现有 HTTP 客户端行为测试。M1 预约调度、M2 审批/outbox、M3、管理写接口、外部通知和云部署不在本轮交付范围，继续明确返回未实现。
