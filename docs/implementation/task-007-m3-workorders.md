# M3-T01：报修、维修封锁及验收恢复初版

2026-10-21：用户授权按推荐下一阶段继续完成初版。本轮本地实现 M3、M1 维修来源入口、D 委托上下文、公开契约与页面，追加迁移及真实 DB/HTTP 验收。不推送、不提交、不修改系统/Python/代理，不下载新依赖。

## 默认政策与边界

有当前有效报修权限且教室范围允许的用户上报整室故障。管理范围内的派单人选择具备当前有效维修权限、且覆盖该教室的维修人员。仅被指派者可开始/完工。维修开始先保存封锁意图并经HTTP确认M1当前ACTIVE后才维修中；完工转待验收仍封锁。授权房管/管理人员验收且不能为维修人；验收失败回维修，成功保存释放意图，确认RELEASED才关闭。本人关闭后一次1至5分评价。

未发出封锁的NEW/ASSIGNED允许报告人按本人取消资格或授权管理范围取消；封锁意图发出后不能借取消跳过验收。默认响应24小时、维修48小时、验收24小时，政策版本快照；到期保存一次升级事件供管理查询，不自动关闭或解封。外部真实推送及完整D通知后续补齐，不把升级事件当外部推送。

M3封锁使用真实开始时间、整室无固定终点，并与个人/M2争用相同room事务锁。可叠加既有M1/M2来源及另一维修；不自动取消/覆盖它们，新分配立即拒绝。解除只影响本工单来源。既有个人预约查询增加维修影响提示，原状态保留；其他消息通知仍有后续工作。

## 工程与验收

工作流持久意图、状态与审计同事务，HTTP在外；operationId和revision固定重试，来源查询确认、租约结果fence防迟到覆盖；释放未知保持待处理，不能假报关闭。M3独立服务凭据仅在本地启动进程注入。用户bearer不落库，所有公开写UUID幂等键、严格DTO与版本检查。

验证正常链、多工单只结束一张仍封锁、既有M2/个人记录保持、验收失败/自验/越权/错误维修人员、重复/并发/重启/丢响应、超时升级去重、空库迁移/种子及既有身份/预约/审批回归。仅实际运行可记通过，浏览器人工验收独列。关键检查进行一次隔离破坏实验后恢复并重跑。

公共开放与管理权限分开解释：m3.work-orders.create的SELF/DEPARTMENT报修资格可覆盖不限制院系的公共教室；m3.dispatch/repair/accept等管理动作的DEPARTMENT仅覆盖归属本院系且院系非空的教室。公共开放不将维修管理权限扩大至其他院系，MANAGED_ROOMS和ALL仍按对应授权判断。D/core与workflow同一语义，避免派单通过后无法开始。
