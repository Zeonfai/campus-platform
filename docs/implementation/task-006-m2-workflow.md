# TASK-006 / M2-T01：整室申请与真实资源写回

2026-10-20：用户明确要求“继续按要求推进项目，具体什么要求按你推荐的来，先不推给他们一起做”。据此采用推荐默认业务政策继续本地实现，属于架构负责人的本轮授权，不表示全组评审或人工验收已经完成。

## 范围与默认政策

申请资格取 D 当前有效 m2.applications.create 权限及教室数据范围。申请只接受未来含时区整点区间，待审批不预占资源。默认政策先院系审批再教室管理员审批，至少两步，禁止本人自审及同一个人完成多个步骤；步骤角色、范围和总超时保存在版本化政策内，新申请冻结政策快照。默认总期限48小时，与使用开始时间取较早值。申请人可在使用开始前撤回，超时未完成自动撤销。

申请本地版本与资源命令版本分别递增。最终审批先进入资源同步状态，同一事务保存申请、审批事实、审计和 outbox。提交后通过真实 HTTP 调用 M1，资源确认且本地提交后才批准。冲突、未知网络结果和已批准明确区分；超时不能视为失败后直接生成新占用。

已发出或可能发出占用的撤回/过期进入 RELEASE_PENDING，保存更高版本的释放命令，确认后终态。释放只解除本申请来源。工作任务使用租约和数据库领取、有限退避及持久结果，固定 operationId/revision 重放。完成结果核对本地当前版本/意图，迟到成功不能复活已撤回记录。用户 bearer 不保存到 outbox、数据库或日志。

## 路径与边界

workflow 的 M2 目录、服务级数据库迁移及种子；公开契约和调用 SDK；core 的 D 教室上下文及演示授权；web 的 M2 页面；真实数据库/HTTP验收工具。不改已执行迁移，不直连 core 业务表，不增加系统工具或依赖，不创建提交、远程仓库或部署。

新增内部 GET /internal/v1/identity/rooms/{roomId} 使用服务与原用户双重身份，仅按 m2.applications.create 权限范围读取启用教室，不借用审批权限。workflow 仍须验证申请所有权、当前步骤和角色。角色匹配与 scope 必须同时满足，不借用无关 ALL 权限。

## 验收

真实双数据库与双服务：申请→两人顺序审批→HTTP占用→M1查询不可用→撤回→恢复。覆盖本人/院系/教室范围、禁止自审及重复审批人、幂等、旧版本、占用冲突、持久重试与重启、撤回和迟到占用回执竞态、政策快照和超时。空库追加迁移、幂等种子、类型/构建及既有身份/调度回归。实际完成项与未执行项分别记录，浏览器人工验收另列。
