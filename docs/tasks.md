## 4. 骨架交接标准

第一条样例范围限定为：演示账号登录 → 教室座位查询 → M2 最简申请 → 授权审批 → 真实 HTTP 占用 → 学生查询该时段不可用 → 授权释放后恢复。

骨架必须同时验证：

1. 从空库执行全部迁移成功，种子重复执行不重复生成账号/教室。
2. 相同座位、相同时段并发不能双重成功；整室占用与个人预约不能冲突落库。
3. 无权限审批和非法输入被拒绝。
4. 重复占用/释放不产生额外副作用，网络失败不误报最终成功。
5. 多级审批、超时和释放补偿结果必须可追踪；尚未完成的真实通知、M1后续业务等继续明确保留，不能用假成功接口掩盖。
6. 另一位成员能仅凭 README 启动和验证；有困难就补说明。

交接时机已在2026-10-22调整为冻结可运行初版、准备上传并接入团队，替代10月20日暂缓安排。主要流程已粗验，但每位成员仍需独立启动、说明成功/失败场景，按任务分支提交可审查切片。当前两级审批和维修链已有实现，不重写骨架。
