# 本轮签到、通知与管理功能体验

本轮是TASK-009本地增量，尚未人工验收或上传。无需重建环境、重新安装依赖或重新生成.env；当前机器已应用追加迁移和幂等演示权限种子。Docker须处于运行状态。

## 启动

在WSL现有项目根目录执行nvm use，然后pnpm dev，打开http://localhost:5173。密码仍从本机.local/demo-accounts.json查看，不发送到群聊或Git。新功能权限刚补入时，请退出后重新登录刷新导航权限。

## 1. 学生预约和签到

使用demo-student-a进入“预约自习座位”，选择未来整点及开放时间内的座位并预约。每条记录展示其自己的签到窗口，默认[开始前15分钟,开始后15分钟)，截止时刻不能签到。已存在的旧预约不追溯记违约。

退出，使用demo-manager-a进入“预约管理与规则”，选择演示教室A101，点击“查看今天签到码”。它显示北京日期和8位当天码，需在教室现场展示。再切回学生，在对应预约输入该码签到；成功后状态变为已签到。其他教室或其他日期的码不能用。

若想尽快试签到，可先用demo-admin把“签到提前分钟”改为60并保存，再新建下一整点的预约；必须仍在演示开放时间08:00～22:00内。新规则仅影响新预约，旧记录窗口不会变化。体验后可恢复默认15，不需要改数据库或机器时间。

## 2. 提醒和超时

未签到预约在开始前15分钟、开始后10分钟生成站内消息，到“我的通知”刷新查看并标记已读；初版未接邮件/微信。开始后15分钟仍未签到，后台扫描后状态变“未签到取消”，座位释放，记录一次违约。初版不自动封禁；资源停用或签到窗口内受维修影响的预约免罚。签到后到结束时间后台自动完成。

扫描间隔约5秒，重启会按持久记录继续处理，不要求网页一直开着。无需通过修改真实业务时间来赶流程；自动测试已经覆盖这些时间边界，实际体验可以分时进行。

## 3. 再次预约原座位

在预约页上方选择新的未来起止时间，再在历史预约点击“按上方新时段再约原座位”。会重新校验开放规则、权限和冲突，成功后生成新预约，不复制旧签到或占用。如果时段冲突会失败，不能直接覆盖别人的预约。

## 4. 管理查询

demo-manager-a可查看自己管理教室的签到码、指定区间的个人预约/M2/M3来源和预约统计。来源中包含已释放/取消记录，应同时看状态和时间。demo-department-a按所属院系管理，公共教室不意味着跨院系管理；demo-admin可全域查询和改预约政策。

统计按所选区间截取，单位为“座位小时”。已签到小时来自已签到预约的时段，不代表真实在座时长；整室申请与维修不计入个人预约统计。政策修改有版本，遇到冲突先重新读取，旧预约保持原快照。
