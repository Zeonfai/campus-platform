## 当前启动方法

在 WSL 项目根目录：

```bash
nvm use
pnpm dev
```

`pnpm dev` 先生成契约/构建公共包，再由 `tools/dev-local.mjs` 启动前端和两个后端。它检查已有本地 development/test 配置、loopback 服务和数据库，仅在进程中给两后端提供彼此独立的随机 M2/M3 服务令牌及本地 core origin，不写 .env、不保存密钥。已有两端令牌不一致时拒绝启动。单独启动后端或生产部署必须正式配置对应服务身份；生产禁止使用本地启动器。

访问/login、/directory、/bookings、/booking-operations、/notifications、/applications、/work-orders。密码只在本机私密文件中由本人查看；用户会话仅在浏览器内存，刷新后重新登录。M2演示为学生申请后院系/教室管理员顺序审批；M3为学生报修、manager-a派给department-a维修、manager-a验收后本人评价。原主要流程已于10月22日粗验，本轮新增页面尚未人工体验。签到默认[-15min,+15min)，提醒-15/+10、+15未签取消；旧预约免罚，仅新预约启用违约。管理码、来源/统计和通知分别在/booking-operations、/notifications，详见 [TASK-009](implementation/task-009-booking-lifecycle.md)。

服务 `/health/live` 与 `/health/ready` 区分存活与数据库基础就绪，均不证明所有业务完成。M2/M3未正确配置HTTP origin/独立服务身份时业务失败关闭，健康检查仍只说明基础设施。
