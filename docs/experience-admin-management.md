# 公共管理初版体验

当前本地分支feat/admin-management。上轮签到版本已推送feat/booking-lifecycle；本轮D管理与CI文件尚未推送。Docker须运行；当前机器已应用第5条core迁移，不要重建环境、清库或重生成.env。

## 启动和登录

在WSL项目目录执行nvm use和pnpm dev，打开http://localhost:5173，使用本机.local/demo-accounts.json中demo-admin登录，进入侧栏“公共管理”（/admin）。密码不要发群聊或上传。

建议先查看原有数据，新增单独的体验教室、座位和角色；不要随意删减原演示角色授权。管理写入有版本检查，遇409须重新选择记录或重新读取规则；旧输入可以对照，但不会自动用新版本覆盖别人修改。

## 院系与角色

院系可登记/改名，本轮没有院系本身的停用或删除。角色可设置名称、数据范围和真实权限目录中的权限；不要通过名字猜权限。名称唯一，教室/座位编号去空白并统一大写。

角色或用户安全配置需要该动作全域权限，不能授予本人未持有的权限或更大范围。更改角色会使相关用户会话失效；重新登录后看新权限。系统禁止移除最后有效的全域用户/角色管理员。

## 教室、座位与开放时间

1. 新建体验教室，选择归属院系、专属属性与启用状态。归属与专属属性创建后固定；其他名称、编号、启用状态可改。
2. 在该教室添加座位，选择无插座/固定插座/移动导轨插座；房内编号不能重复。座位不能直接挪到另一教室。
3. 读取整周开放规则，选中星期和整点起止时间后保存。每次保存替换全周，未选日关闭；全部不选表示整周关闭。结束可24:00，单段不跨日。
4. 用学生账号在范围内查询新座位。新教室未配置开放时间时不可预约；停用后不可新约，既有记录保留。
5. 管理员按当前版本修改资料。两窗口同时编辑同一记录时，后保存的旧版本应提示冲突；必须显式重读后再修改。

## 用户授权

针对已有账号选择角色、指定教室与启用状态，填写理由。不能修改自己的访问授权，不能撤空最后一名安全管理员。停用或改授权可能影响该用户正在处理的审批/维修，请先交接；已登录的目标用户需要重新登录。

本轮不提供公开注册、批量导入、修改账号院系或改密码。不要为体验而修改真实生产账号；示例数据仍为本机合成演示。

## 审计和自动检查

审计可按操作者、动作、目标精确筛选并分页，包含管理修改的真实操作者、理由、traceId和时间。此页是core审计，workflow仍保存自己的流程审计，不能视作已跨库汇总。

停止dev/watch后，已有依赖和数据库准备好可运行bash tools/ci-check.sh，一次执行构建和所有真实数据库测试。不要与开发构建同时运行；脚本不安装依赖、不初始化配置、不启停你的数据库。平台CI配置与边界见ci.md，目前只完成本地运行验证。
